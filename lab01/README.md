# EXERCISE 4
## Task 1 - Open the New Project
**Що зроблено:** створено нову програму `ParallelMV.cpp` й для тесту виведено повідомлення "Serial matrix-vector multiplication program"

## Task 2 - Initializing the parallel program
**Що зроблено:** протестовано роботу `ParallelMV.cpp`, а саме вивантажено повідомлення на кількох потоках.
**Перевірка:** кожен рядок відповідає окремому процесу, який виконується одночасно; якщо вивід з’являється кілька разів, це означає, що MPI успішно працює, а середовище ініціалізовано правильно. Для тесту підключіть команди в bash у послідовності:
`mpic++ src/ParallelMV.cpp -o ParallelMV`
`mpirun -np 4 ./ParallelMV`

## Task 3 - Determine the Number of Processes
**Що зроблено:** Підключено бібліотеку `mpi.h`, створено основну структуру MPI-програми. У функції `main()` додано ініціалізацію середовища MPI (`MPI_Init`), визначення кількості процесів (`MPI_Comm_size`) і рангу кожного процесу (`MPI_Comm_rank`). Повідомлення про запуск і кількість доступних процесів виводиться лише головним процесом (ранг 0), інші процеси виводять свій номер

## Task 4 - Input the Matrix and Vector Size
**Що зроблено:** створено функцію `ProcessInitialization(...)`, яка тепер враховує паралельний режим.
Вводити розмір матриці дозволено лише процесу з рангом 0, який перевіряє, що Size має бути більший, ніж кількість процесів і кратно кількості процесів. Після цього значення Size передається всім процесам через `MPI_Bcast`

### Task 5 — Input the Initial Data
**Оновлено:** функцію `ProcessInitialization(...)`, яка запитує розмір матриці лише у процесу з `ProcRank == 0`.  
Після перевірки ділення на кількість процесів — значення `Size` передається іншим процесам через `MPI_Bcast`.  
Також додається змінна `RowNum = Size / ProcNum` для визначення кількості рядків, які обробляє кожен процес.

### Task 6 – ProcessTermination: звільнення пам’яті
**Додано:** функцію `ProcessTermination(...)`,  яка звільняє усю динамічно виділену пам’ять після завершення обчислень.

### Task 7 — Data Distribution та Test Distribution
**Що зроблено:** Реалізовано функцію `DataDistribution(...)`, яка розподіляє вхідні дані між процесами. Також додано функцію `TestDistribution(...)`, яка перевіряє коректність розподілу даних.
**Логіка:** Розподіл виконується рівномірно — кожен процес отримує `RowNum = Size / ProcNum` рядків матриці.  
Вивід синхронізується за допомогою `MPI_Barrier`, щоб процеси не друкували одночасно.

### Task 8 — Parallel Matrix-Vector Multiplication
**Що зроблено:** Реалізовано паралельне множення матриці на вектор, де кожен процес обчислює свій фрагмент результату.  
Усі обчислення виконуються одночасно, після чого локальні результати об’єднуються у спільний вектор результатів.
**Додано:**  Функцію `ParallelResultCalculation(...)`, яка виконує множення частини матриці (`pProcRows`) на спільний вектор (`pVector`) для кожного процесу; функцію `TestPartialResults(...)` для перевірки проміжних обчислень

### Task 9 — Gather the Results
**Що зроблено:** реалізовано об’єднання частин вектора результатів, що були обчислені на різних процесах. Для цього створено функцію `ResultReplication(...)`, яка копіює частини локальних результатів (`pProcResult`) із кожного процесу в єдиний глобальний вектор результатів (`pResult`) на всіх процесах.

### Task 10 — Test the Parallel Program Correctness
**Додано:** Функцію `TestResult(...)`, яка викликає послідовну функцію `SerialResultCalculation(...)`, порівнює кожен елемент послідовного результату `pSerialResult` з паралельним результатом `pResult` і виводить повідомлення про збіг або розбіжність результатів.

### Task 11 — Implement the Computations for Any Matrix Sizes
**Що зроблено:** Розширено програму для роботи з неквадратними (прямокутними) матрицями. Додано окремі параметри `Rows` і `Cols`, які дозволяють задавати кількість рядків і стовпців незалежно. Перероблено всі функції, що працюють із розмірами, пам’яттю, та комунікаціями між процесами. Кожен процес тепер отримує `RowNum = Rows / ProcNum` рядків, незалежно від кількості стовпців.

### Висновки до роботи
Отримані результати показують, що ефективність паралельних обчислень значною мірою залежить від співвідношення між часом обчислень і часом комунікації.
Для невеликих задач паралелізація не лише не прискорює, а й може сповільнити виконання через накладні витрати на передачу даних між процесами.
Проте при збільшенні розміру задачі частка комунікаційного часу зменшується, і паралельні алгоритми поступово починають перевершувати послідовні.

У контексті важливих обчислювальних задач (наукове моделювання, обробка великих масивів даних, машинне навчання) навіть невелике зменшення часу виконання може мати критичне значення.
Наприклад, скорочення часу симуляції кліматичних моделей або навчання нейронних мереж на кілька годин може зменшити споживання енергії, прискорити прийняття рішень або дозволити виконати більше експериментів за той самий час.

Таким чином, аналіз різниці у часі між послідовними та паралельними реалізаціями дозволяє оцінити доцільність розпаралелювання та визначити, за якого обсягу задачі воно починає приносити реальний виграш у продуктивності.
